# Тест-план учебной операционной системы

## 1. Введение
Цель тестирования — убедиться, что учебная операционная система выполняет все заявленные функции, соответствует нефункциональным требованиям и корректно обрабатывает ошибочные ситуации[cite: 103].
Область тестирования — все модули системы: db.py, kernel.py, auth.py, fs.py, scheduler.py, syscalls.py, shell.py[cite: 103].
Тестирование проводится силами одного разработчика (студента) в течение трёх дней (дни 7–9 раздела)[cite: 103].

## 2. Объём тестирования
В объём входит:
- модульное тестирование каждой функции db.py, kernel.py, auth.py, fs.py, scheduler.py[cite: 104];
- функциональное тестирование системных вызовов syscalls.py[cite: 104];
- интеграционное тестирование связок между модулями[cite: 104];
- системное тестирование сквозных сценариев работы ОС[cite: 104];
- регрессионное тестирование после исправления дефектов[cite: 104].

В объём не входит:
- тестирование производительности под высокой нагрузкой[cite: 104];
- тестирование на реальном аппаратном обеспечении[cite: 104];
- тестирование сетевых сценариев[cite: 104];
- тестирование графического интерфейса (его нет)[cite: 104].

## 3. Виды тестирования
Применяются следующие виды:
- Модульное тестирование — для каждой отдельной функции[cite: 104].
- Функциональное — для системных вызовов[cite: 104].
- Интеграционное — для связок shell -> syscalls -> fs и shell -> syscalls -> scheduler[cite: 104].
- Системное — для сквозных сценариев[cite: 104].
- Регрессионное — после каждого исправления дефекта[cite: 104].

## 4. Ресурсы
Инструменты: VS Code, Python 3.10+, SQLite, SQLite Viewer, Git[cite: 104].
Документация: матрица трассируемости из 03_Module_Specifications.md[cite: 104].
Тестовые данные: создаются скриптами и не требуют ручной подготовки[cite: 104].

## 5. Расписание
День 7 — разработка стратегии, тест-плана, тест-кейсов, модульных тестов[cite: 104].
День 8 — функциональное и интеграционное тестирование[cite: 104].
День 9 — системное и регрессионное тестирование, итоговый протокол[cite: 104].

## 6. Критерии
Критерии начала: все модули реализованы, интеграционные тесты проходят, отчёт о разработке сдан[cite: 105].
Критерии окончания:
- все модульные тесты проходят[cite: 105];
- все функциональные тесты проходят[cite: 105];
- все интеграционные тесты проходят[cite: 105];
- все системные сценарии выполнены[cite: 105];
- найденные дефекты зафиксированы в баг-репортах[cite: 105];
- требования верифицированы по матрице трассируемости[cite: 105];
- итоговый протокол оформлен[cite: 105].
