# Проектная документация учебной ОС "EduOS"
**Раздел:** Определение границ операционной системы и разработка нефункциональных требований  
**Тема:** Разработка требований к программным модулям на основе проектирования системы  

---

## 1. Концепция операционной системы
**EduOS** представляет собой учебную модульную монолитную операционную систему, функционирующую на базе среды Python с использованием базы данных SQLite в качестве виртуального физического носителя и реестра ресурсов.  

**Основная идея:** Реализация базовых сервисов ОС (управление процессами, оперативной памятью, авторизацией и изолированной файловой системой) с контролем выполнения через ядро посредством системных вызовов и подсистемы аутентификации.

---

## 2. Границы операционной системы (Scope)

### Входит в границы системы:
1. **Управление процессами:** Создание, отслеживание состояний, остановка и имитация работы планировщика процессов (Round-Robin).
2. **Управление памятью:** Имитация выделения и освобождения страниц виртуальной памяти с ограничением по лимиту.
3. **Файловая система:** Организация таблицы файлов/каталогов и разграничение доступа в рамках SQLite.
4. **Безопасность и разграничение прав:** Аутентификация по логину/паролю (хэширование SHA-256), проверка ролей (`admin`, `user`).
5. **Командная оболочка (Shell):** Текстовый CLI-интерфейс для взаимодействия с ядром через системные вызовы.
6. **Журналирование:** Автоматическая фиксация каждого системного вызова в SQLite.

### Не входит в границы системы (с обоснованием):
1. **Прямое управление аппаратным обеспечением (Hardware Drivers):** Заменено заглушками из-за высокого уровня сложности аппаратного уровня в рамках академических часов.
2. **Поддержка сетевого стека (TCP/IP):** Сетевое взаимодействие исключено для концентрации на локальных сервисах ядра.
3. **Графический интерфейс (GUI):** Исключён для снижения избыточности кода; используется CLI.
4. **Аппаратные прерывания:** Имитируются программными сигналами в пользовательском пространстве.

| 1 | Вход в систему | Пользователь | `sys_login(username, password)` | `shell.py`, `kernel.py`, `syscalls.py` (`auth`), `db.py` |

| 4 | Запуск процесса | Пользователь/Админ | `sys_exec(program_name, mem_limit)` | `shell.py`, `kernel.py`, `syscalls.py` (`process_manager`), `db.py` |
| 5 | Просмотр процессов | Пользователь/Админ | `sys_ps()` | `shell.py`, `kernel.py`, `syscalls.py`, `db.py` |

| 10 | Завершение работы ОС | Админ | `sys_shutdown()` | `shell.py`, `kernel.py` |

## 4. Нефункциональные требования

### Производительность:
* Время обработки одного системного вызова ядра не должно превышать **50 мс** (проверяется функцией `time.perf_counter()`).
* Поддержка не менее **10 одновременно активных виртуальных процессов**.
* Максимальное время отклика командной оболочки при вводе команды — не более **100 мс**.

### Надёжность:
* При возникновении фатальной ошибки в пользовательском процессе ядро должно корректно перехватывать исключение, останавливать процесс и записывать лог без падения системы.
* При попытке выделить память сверх установленного лимита (1024 КБ) вызов отклоняется с кодом ошибки `OUT_OF_MEMORY`.
* База данных SQLite должна автоматически восстанавливать целостность таблиц при сбое во время запуска.

### Безопасность:
* Пароли хранятся строго в виде хэш-строк **SHA-256**.
* Доступ к системным файлам конфигурирования разрешён только пользователям с ролью `admin`.
* Все системные вызовы заносятся в таблицу `syscalls_log`.

### Поддерживаемость:
* Исходный код разбит на узкоспециализированные модули (`shell`, `kernel`, `syscalls`, `db`).
* Размер одного файла кода не должен превышать **300 строк**.

### Ресурсоемкость:
* Выполнение на стандартном интерпретаторе Python версии 3.10+ без внешних зависимостей pip.
* Занимаемый объем памяти БД не должен превышать **50 МБ**.

## 6. Описание созданного прототипа
В рамках Занятия 1 созданы и протестированы базовые компоненты:
* **`src/db.py`**: Автоматически инициализирует базу данных `db/os.sqlite` с таблицами `users`, `processes`, `files`, `syscalls_log`.
* **`src/syscalls.py`**: Содержит функции с журналированием `sys_echo` и `sys_get_users`.
* **`src/shell.py`**: Командная оболочка CLI, транслирующая команды пользователя в ядро.

Запуск командной оболочки выполняется из корня проекта:
